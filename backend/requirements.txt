# Installation :
#   cd backend
#   python -m venv .venv
#   .venv\Scripts\activate        (Windows)  |  source .venv/bin/activate  (macOS/Linux)
#   pip install -r requirements.txt
#
# Versions figées volontairement (reproductibilité des builds et de la CI).
#
# CE FICHIER EST LA SOURCE, PAS CE QUI EST INSTALLÉ EN CONTENEUR.
#
# Il ne verrouille que les dépendances DIRECTES. Les transitives — Werkzeug,
# Jinja2, itsdangerous... — restaient libres de changer d'une installation à
# l'autre (ticket KAN-102). Deux verrous en sont dérivés, avec les empreintes
# de chaque archive :
#
#     requirements.lock        production, utilisé par backend/Dockerfile
#     requirements-dev.lock    + outils de test et Ruff, utilisé par la CI
#
# Les régénérer après toute modification ici :
#
#     pip install pip-tools
#     pip-compile --generate-hashes --strip-extras \
#                 --output-file=requirements.lock requirements.txt
#
# Les empreintes ne sont pas du zèle : installées avec --require-hashes, elles
# font échouer l'installation si un paquet a été altéré sur l'index.
# ==============================================================================

# Pilote MySQL. database/db.py prévoit déjà l'URL mysql+pymysql:// pour le
# conteneur, mais aucun pilote n'était installé : l'application échouait au
# démarrage dès qu'on la branchait ailleurs que sur SQLite.
PyMySQL==1.1.2

# Dépendance OBLIGATOIRE de PyMySQL face à MySQL 8, et pas une option.
#
# MySQL 8.4 authentifie par défaut avec caching_sha2_password. Deux chemins :
#
#   • le serveur a déjà le mot de passe en cache -> échange par empreinte, et
#     cryptography ne sert à rien ;
#   • PREMIÈRE connexion, ou cache vidé par un redémarrage du serveur ->
#     authentification complète. Sur une connexion non chiffrée, le client doit
#     récupérer la clé publique RSA du serveur et lui chiffrer le mot de passe.
#     PyMySQL délègue ce calcul à cryptography, et sans elle lève :
#         RuntimeError: cryptography is required for sha256_password
#                       or caching_sha2_password
#
# C'est donc la PREMIÈRE connexion de la pile qui échouait — « docker compose up »
# ne pouvait pas fonctionner, et le message n'évoquait ni MySQL ni un paquet
# manquant. Le cas n'avait pas été vu parce que la suite de tests tourne sur
# SQLite, qui n'authentifie rien.
cryptography==46.0.3
